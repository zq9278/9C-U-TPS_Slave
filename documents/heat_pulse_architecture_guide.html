热脉动固件新架构说明

说明对象：基于现有业务逻辑重构后的 UserDrivers、Modules 与 FreeRTOS 任务调用关系。

目录 1. 重构目标 2. 原有业务识别 3. 新分层结构 4. FreeRTOS 任务架构 5. UserDrivers 接入 6. Modules 说明 7. 热脉动控制流程 8. 传感器数据流 9. 命令与遥测流 10. PID 与调参 11. 文件清单 12. 迁移状态 13. 验证结果

1. 重构目标

这次重构不是简单移动文件，而是把原来集中在任务里的业务逻辑拆成可复用模块，让 FreeRTOS 任务只负责调度和队列交互。

新的目标架构遵循下面几条原则：

  • 驱动下沉：硬件器件访问统一走 UserDrivers，再由 BSP 适配 HAL。
  • 模块承载业务：热脉动控制、传感器采样、PID 算法放在 Modules。
  • 任务变薄：任务不直接写复杂业务，只调用模块接口。
  • C 风格对象化：用结构体实例保存状态，用函数第一个参数传入实例指针。
  • 保留协议兼容：上位机命令和遥测帧 ID 继续沿用原协议。
本文档说明的是当前第一版可编译架构。它已经完成主链路迁移，但仍保留部分旧文件用于兼容或后续清理。

2. 原有业务识别

原程序的热脉动核心逻辑可以识别为三条主线：

业务线 原位置 识别出的职责
治疗业务状态 Application/AppMain/TreatmentApp.cpp 处理开始、停止、暂停、恢复、左右眼使能、温度目标、压力目标和治疗倒计时。
传感器采集 Application/Tasks/sensor_task.c 轮询 ADS1248 温度、压力传感器，并写入 gSensorData。
热脉动控制 Application/Tasks/control_task.c 处理控制命令、压力波形、压力 PID、左右温控 PID、执行器输出、遥测和加热盾状态。

原来的主要问题是 ControlTask 承载太多：状态机、PID、执行器、遥测和调试输出混在同一个任务文件里。新架构把它拆成 HeatPulseController 和薄任务 runner。

3. 新分层结构

Core / HAL: CubeMX 生成外设初始化，提供 I2C/SPI/GPIO/TIM/UART HAL handle
BSP: 对 HAL 进行总线和引脚抽象，例如 BspI2c、BspSpi、BspGpio、BspPwm
UserDrivers: 具体器件驱动，例如 ADS1248、压力传感器、24C02、DS18B20
Modules: 业务可复用模块，例如 Sensors、HeatPulse、Pid、Filter
Application Tasks: FreeRTOS runner，负责队列、周期调度、遥测发送
Protocol / App: 上位机协议和治疗业务状态机

依赖方向应尽量保持单向：

Application/Tasks -> Modules -> UserDrivers -> BSP -> HAL

这样做的好处是：驱动可以独立替换，控制算法可以独立测试，任务代码不会继续膨胀。

4. FreeRTOS 任务架构

任务 当前职责 新调用方式
SensorTask 采集温度和压力，更新 gSensorData。 调用 TreatmentSensors_Init() 和 TreatmentSensors_Poll()。
ControlTask 处理控制命令、运行热脉动控制、发送遥测、服务加热盾。 调用 HeatPulseController_HandleCommand() 和 HeatPulseController_Run()。
AppTask 治疗业务状态机，产生 ctrl_cmd_t。 保持原有职责，输出控制命令给 ControlTask。
CommTask 业务串口收发、协议 TX/RX 队列处理。 保持原有通信 runner。
DebugLogTask 处理调试串口 ASCII PID 调参命令。 调参入口改为 HeatPulseController_SetPressurePidGains()。
StorageTask 加载和保存设置。 旧 AT24CXX_* API 已桥接到新 UserEeprom24cxx。
任务调度结构保留了原工程的稳定性，重构主要发生在任务内部调用的模块边界。

5. UserDrivers 接入

新驱动集中在 UserDrivers 下，板级实例由 UserDrivers/user_drivers_board.c 统一绑定。

器件 新驱动 底层资源 全局实例
ADS1248 温度采集 UserDrivers/Ads1248 SPI2、RTD_CS PB12、RTD_START PB15、RTD_RDY PA8 gUserAds1248
压力传感器 UserDrivers/PressureSensor I2C1 PA9/PA10，地址 0x78 gUserPressureSensor
24C02 EEPROM UserDrivers/Eeprom24cxx 软件 I2C：EE_SCL PA11、EE_SDA PA12 gUserEeprom24c02
DS18B20 UserDrivers/Ds18b20 单总线：TS1 PB5 gUserDs18b20
EEPROM 旧代码里的 WP 曾使用 PA9，但该引脚也是 I2C1_SCL。新板级绑定没有继续使用这个写保护脚，避免和压力传感器 I2C 时钟冲突。

6. Modules 说明

Modules/Sensors

传感器模块负责把底层器件驱动读数整理成系统统一的 sensor_data_t。

  • 交替读取 ADS1248 的左右温度通道。
  • 每 10ms 读取压力传感器。
  • 保留原逻辑中的 3 点中值滤波。
  • 写入 gSensorData.tempL/tempR/pressL/pressR/tick。

Modules/HeatPulse

热脉动控制模块是本次重构的主模块，负责从控制配置和传感器快照计算执行器输出。

  • 处理 CTRL_CMD_START/STOP/PAUSE/RESUME/UPDATE_CFG。
  • 维护波形锚点 wave_anchor_tick 和暂停恢复位置。
  • 计算 60 秒周期内的 rise/hold/pulse_on/pulse_off 阶段。
  • 运行压力 PID，输出气泵 PWM。
  • 运行左右温控 PID，输出加热 PWM。
  • 调用 TreatmentActuators 实际驱动泵、阀、加热 PWM。

Modules/Pid

新的 PID 是可多实例复用模块，每个 PidController 独立保存积分、微分滤波和调试项。

Modules/Filter

目标窗口滤波模块用于在一段时间或一批样本里选择最接近目标值的样本。目前已作为通用工具加入构建，后续可用于显示值、稳定段筛选或自动调参辅助。

7. 热脉动控制流程

热脉动的核心节奏仍然沿用原业务：一个周期 60 秒，分为上升、保压和脉动挤压三段。

阶段 默认时长 压力目标 执行器动作
rise 2 秒 从 0 线性上升到目标压力。 打开波形阀，压力 PID 控制气泵补压。
hold 2 秒 保持目标压力。 打开波形阀，压力 PID 控制气泵维持压力。
pulse_on 脉冲高压半周期 目标压力。 打开波形阀，气泵参与补压。
pulse_off 脉冲低压半周期 0 kPa。 关闭波形阀，气泵 PWM 置 0。
pause 由上位机控制 冻结治疗时间位置。 所有输出进入安全空闲态。 
ControlTask loop:
  receive ctrl_cmd_t
  HeatPulseController_HandleCommand()
  HeatPulseController_Run(sensor, now, dt)
  service telemetry
  service heater shield status

8. 传感器数据流

传感器链路现在从任务中抽到了 TreatmentSensors 模块：

SensorTask
  -> TreatmentSensors_Init()
      -> UserDrivers_BoardInit()
      -> UserAds1248_Init()
  -> loop:
      -> UserAds1248_ReadTemperatureC()
      -> UserPressureSensor_Read()
      -> 3-point median pressure filter
      -> gSensorData
数据 来源 写入字段
左温度 ADS1248 USER_ADS1248_CHANNEL_HEAT1 gSensorData.tempL
右温度 ADS1248 USER_ADS1248_CHANNEL_HEAT2 gSensorData.tempR
左压力 I2C1 压力传感器 gSensorData.pressL
右压力 当前镜像左压力，保留右路扩展位 gSensorData.pressR

9. 命令与遥测流

命令流

USART3 RX
  -> uart_driver parser
  -> HostProtocol dispatch
  -> gAppEventQueue
  -> AppTask / TreatmentApp
  -> gCtrlCmdQueue
  -> ControlTask
  -> HeatPulseController

TreatmentApp 仍然负责业务层判断：开始、停止、暂停、左右眼使能、目标温度、目标压力和治疗倒计时。

遥测流

HeatPulseController_Run()
  -> HeatPulseRuntime
  -> ControlTask service_telemetry()
  -> gTxQueue
  -> CommTask
  -> USART3 TX
遥测 帧 ID 节拍
左压力 0x1101 100 点/秒
左温度 0x1103 50 点/秒
右温度 0x1104 50 点/秒
当前阶段 0x110B 跟随温度节拍

10. PID 与调参

新 PID 使用 PidController，每个控制环一个实例：

  • pressure_pid：压力闭环，输出范围 0 到 255。
  • heat_left_pid：左温控闭环，输出范围 0 到 1999。
  • heat_right_pid：右温控闭环，输出范围 0 到 1999。

压力 PID 仍然按阶段分三组参数：

阶段 默认参数 调试命令
RISE Kp=80 Ki=0 Kd=0 兼容旧调参口径 R kp ki kd
HOLD Kp=140 Ki=8 Kd=0 兼容旧调参口径 H kp ki kd
PULSE Kp=220 Ki=0 Kd=0 兼容旧调参口径 P kp ki kd
新 PID 内部使用真实 dt_s 参与积分和微分。为了兼容旧 PID 调参工具，DebugLogTask 会把旧口径参数换算成新 PID 内部参数。

PID 调试二进制帧仍通过调试串口输出，版本号已改为 2，曲线字段仍包含 p/i/d/error/output/setpoint/feedback。

12. 迁移状态

项目 状态 说明
ADS1248 采温 已迁移 SensorTask 现在通过 TreatmentSensors 调用 UserAds1248。
压力采样 已迁移 通过 UserPressureSensor 读取，右路仍按旧逻辑镜像左路。
EEPROM 已桥接 旧 AT24CXX_* API 继续存在，底层改用 UserEeprom24cxx。
压力波形 已迁移 由 HeatPulseController 内部计算。
温控 PID 已迁移 左右温控各自使用一个 PidController 实例。
压力 PID 调参 已迁移 调试串口 ASCII 命令接入新热脉动模块。
安全任务 保留原状 仍通过 APP_EVT_SAFETY_FAULT 通知业务层停止。
