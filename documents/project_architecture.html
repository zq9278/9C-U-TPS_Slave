项目架构总览

当前工程采用 App/System 负责任务编排，Modules/* 按业务职责拆分，协议层统一把 RK3576 帧转换成 app_cmd_t，再由 AppTask 统一收口成配置更新、控制命令和采样命令。所有上行遥测统一进 gTxQueue，由 CommTxTask 独占串口发送。

当前代码里的关键事实：
  • SensorTask 周期是 5ms，温度采样是非阻塞状态机。
  • ControlTask 周期是 2ms，负责闭环和遥测节拍。
  • 控制温度目标值带 +1°C 偏移，上传给 RK3576 的温度带 -1°C 偏移。
  • 发送侧滤波开关 RK3576_TELEMETRY_FILTER_ENABLE 当前为 0U。

2. 架构图与数据流

命令收口原则

协议层只做帧解析，不直接动硬件。真正的业务分发都在 AppTask 收口。

传感器解耦原则

采样模式通过 sensor_cmd_t 下发，SensorTask 不直接依赖控制器内部状态。

串口出口唯一

所有上行状态与遥测都先进 gTxQueue，由 CommTxTask 独占发送。

协议文档里需要特别标出的实际约定：
  • 0x10C0 的值不是任意枚举，而是当前代码固定的 1/2/3 三档。
  • 0x10C4 的值不是布尔意义的“开启/关闭”，而是当前代码硬编码的 0=暂停，非0=恢复。

8.1 APP_CMD_START 的真实动作顺序

  1. 如果左右眼都未选，默认把 press_enable_L 和 press_enable_R 设为 1。
  2. 把 paused 清零，设置 cfg.running = 1 和 gTreatmentRunning = 1。
  3. 调用 send_sensor_mode(resolve_temperature_mode(&cfg), ...)。
  4. 下发 CTRL_CMD_UPDATE_CFG。
  5. 下发 CTRL_CMD_START。

8.2 APP_CMD_STOP 的真实动作顺序

  1. 读取并消费挂起的 stop_reason。
  2. 清运行态和暂停态。
  3. 发送 TEMP_ACQUIRE_MODE_IDLE 给 SensorTask。
  4. 如果没有故障停机原因，则默认上报手动停止。
  5. 调用 enqueue_tx_u8(0x110C, stop_reason)。
  6. 再发送 CTRL_CMD_STOP 让控制器收口。

11. 传感器采样与交互

11.1 温度采样模式

模式 含义
TEMP_ACQUIRE_MODE_IDLE空闲，不做正常温度采样。
TEMP_ACQUIRE_MODE_DUAL_SCAN双眼交替采样左右温度。
TEMP_ACQUIRE_MODE_SINGLE_LEFT只采左眼温度，对应锁定 Heat2 温度通道。
TEMP_ACQUIRE_MODE_SINGLE_RIGHT只采右眼温度，对应锁定 Heat1 温度通道。

11.2 ADS1248 当前采样状态机

SWITCH_CHANNEL
-> 写 MUX0 / MUX1 / SYS0 / IDAC0 / IDAC1
-> WAIT_DISCARD_SAMPLE
-> DRDY 就绪后读首样本并丢弃
-> WAIT_VALID_SAMPLE
-> DRDY 就绪后读有效样本
-> 写入 gSensorData.tempL / tempR
-> 切换下一目标通道

11.3 状态机与任务节拍关系

  • SensorTask 每 5ms 只推进一步，不再阻塞等待 WaitDrdy()。
  • 单眼模式下不再来回切换无关通道。
  • 双眼模式下每次换道都会丢弃首样本，再读第二笔有效值。

11.4 传感器命令如何介入

  • resolve_temperature_mode() 根据左右眼使能和眼罩在位状态给出采样模式。
  • send_sensor_mode() 使用 xQueueOverwrite(gSensorCmdQueue, ...) 保证只保留最新策略。
  • SensorTask 读取最新 sensor_cmd_t 后切换温度模式和日志抑制位。

12. 控制闭环

  1. ControlTask 接收 ctrl_cmd_t。
  2. 控制器 HandleCommand() 更新状态或配置。
  3. 读取 gSensorData 作为本周期测量值。
  4. 调用 TreatmentAppController_Run()。
  5. 压力模块生成计划并驱动气泵 / 阀。
  6. 加热模块根据左右眼温度和目标值运行 PID 并输出 PWM。
当前热控目标值计算： 
effective_target_left  = cfg.temp_target + HEAT_TARGET_OFFSET_LEFT_C
effective_target_right = cfg.temp_target + HEAT_TARGET_OFFSET_RIGHT_C

13. 遥测与滤波

13.1 发给 RK3576 的温度值形成链路

ADC 原始温度
-> Rk3576TelemetryMapTempLeft / Right
-> raw_temp + RK3576_TEMP_UPLOAD_OFFSET_*_C
-> (如果启用) TargetWindowFilter
-> enqueue_tx_f32(0x1103 / 0x1104, value)
-> CommTxTask
-> UART3

13.2 当前发送侧滤波行为

  • 滤波器对象在 app_tasks.c 的 Rk3576TelemetryFilterState。
  • 当前只覆盖：左压力、左温、右温。
  • 滤波目标值跟随上一窗口输出，用于抑制曲线抖动。
  • 宏 RK3576_TELEMETRY_FILTER_ENABLE = 0U 时，这整段逻辑会旁路。

13.3 暂停期间的发送策略

  • 暂停时不发温度和压力到 RK3576。
  • 恢复后重启节拍，不补发暂停期间的数据。

14. 安全保护与停机

14.1 SafetyTask 检查项

检查项 逻辑
软件过温gSensorData.tempL > TEMP_MAX_C 或 tempR > TEMP_MAX_C。
软件超压左右压力超过 PRESS_MAX_KPA。
OTP 硬件过温右眼 PA6、左眼 PB1，正常高电平，过温变低电平。
保护器件故障左眼 PB0、右眼 PA5 ADC 满量程附近，且眼盾在线时判故障。
眼盾离线 / 保险丝异常由 eye_shield_status 维护状态后参与停机逻辑。

14.2 停机原因码

值 枚举 含义
1STOP_REASON_MANUAL手动停止。
2STOP_REASON_EYE_SHIELD_OFFLINE眼盾不在线。
3STOP_REASON_OVER_TEMP软件过温或 OTP 过温。
4STOP_REASON_OVER_PRESSURE超压。
5STOP_REASON_LEFT_HEATER_PROTECTOR_FAULT左眼保护器件 ADC 故障。
6STOP_REASON_RIGHT_HEATER_PROTECTOR_FAULT右眼保护器件 ADC 故障。

14.3 停机收口链路

SafetyTask 发现 fault
-> set_pending_stop_reason(...)
-> send_ctrl_command(CTRL_CMD_STOP)
-> request_app_stop()
-> AppTask 处理 APP_CMD_STOP
-> enqueue_tx_u8(0x110C, stop_reason)
-> ControlTask / RK3576 同时感知停机

15. 典型流程

设置温度

  1. RK3576 发 0x1002
  2. 翻译为 APP_CMD_SET_TEMP
  3. AppTask 更新 cfg.temp_target
  4. 下发 CTRL_CMD_UPDATE_CFG
  5. 热控模块按 cfg + 1°C 生效

启动治疗

  1. RK3576 发 0x10C1
  2. AppTask 处理默认单双眼选择
  3. 下发温度采样模式
  4. 下发更新配置和启动命令
  5. ControlTask 开始闭环

暂停 / 恢复

  1. RK3576 发 0x10C4
  2. 0=暂停，非0=恢复
  3. 暂停时采样转 IDLE
  4. 暂停时不发温压遥测
  5. 恢复时重新计算单双眼采样模式
